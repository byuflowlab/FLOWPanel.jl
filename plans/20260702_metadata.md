Review & streamline: reflected metadata approach (plans/20260701_metadata_c.md)

Context

plans/20260701_metadata_c.md replaced the hand-maintained SFS if-chains in
src/FLOWPanel_replay.jl with pure reflection: _singleton_tag records the actual
FLOWVPM
binding name at write time, _resolve_singleton resolves it back via getfield at read
time,
and migrate_metadata_toml canonicalizes legacy files. The goal was to kill the "add a
FLOWVPM
singleton upstream, forget to update the chain, replay silently substitutes a
physically different
default" failure mode.

This review checks the implemented code (already committed working-tree changes to
src/FLOWPanel_replay.jl and test/runtests_unit_replay.jl) for correctness/robustness
gaps and
asks whether the remaining enumerated lists can be streamlined while staying robust.

Verified against installed FLOWVPM
(/Users/ryan/Dropbox/research/projects/FLOWVPM.jl):
- SFS types (NoSFS, ConstantSFS, DynamicSFS) are immutable structs → the plan's
immutable-egal claim holds; user-constructed equivalents tag correctly.
- relax_pedrizzetti / relax_correctedpedrizzetti are module-level function bindings
(FLOWVPM.jl:183-184) → reflectable the same way SFS singletons are.
- FLOWVPM has no @deprecated bindings today → _singleton_tag's full-module getfield
scan
currently emits no deprecation noise (but see #5).

The core reflection design is sound. The SFS round-trip, type-validated resolution,
loud
missing-binding errors, and the migration function are correct. The issues below are
gaps where the
plan's own principle ("never silently substitute a physical default") was applied
inconsistently,
plus one clean streamlining win the plan hinted at but didn't take.

Findings (most severe first)

1. _deserialize_relaxation still silently substitutes — the exact failure mode the
plan set out to kill

src/FLOWPanel_replay.jl:682-697. The else branch returns
FLOWVPM.relaxation_correctedpedrizzetti
with no warning. Step 4 of the plan made _deserialize_viscous and
_deserialize_wake_shedding
loud but never touched relaxation. A misspelled or future relaxation tag silently
becomes
corrected-Pedrizzetti — a physically different reproduction with no signal.

2. _relaxation_manifest writes a non-round-tripping tag for any third scheme
(streamlining win)

src/FLOWPanel_replay.jl:227-235. Only two relax functions are hardcoded; the else
writes
string(nameof(typeof(relaxation.relax))), e.g. "relax_pedrizzetti" — without the
"FLOWVPM."
prefix — which then hits the silent else of #1 on read. This is precisely the
enumerated-list
fragility reflection was meant to remove, and it is the one remaining pure singleton
list.
Fix by reflecting the relax function, mirroring the SFS treatment.

3. migrate_metadata_toml injects empty pfield_optargs into every wake entry

src/FLOWPanel_replay.jl:648 uses get!(wmeta, "pfield_optargs", Dict()), so PanelWake
and
nothing wake entries — which never carry FLOWVPM optargs — get a spurious empty
pfield_optargs
table written into the migrated file. Harmless to replay, but pollutes output and
makes migration
non-minimal. Only create/populate the table when there's a legacy key to move.

4. _singleton_tag write is module-generic but _resolve_singleton hardcodes "FLOWVPM."

src/FLOWPanel_replay.jl:153-173. _singleton_tag(mod, obj) emits
"$(nameof(mod)).$name" for any
module, but resolution only understands the FLOWVPM. prefix. Reusing _singleton_tag
with another
module would silently produce unresolvable tags. Low priority (only FLOWVPM is used
today); either
add a comment pinning it to FLOWVPM or derive the module from the tag prefix on
resolve.

5. _singleton_tag scans every binding via getfield — latent deprecation-warning noise

src/FLOWPanel_replay.jl:154-158. Fine today (no FLOWVPM deprecations), but a future
@deprecated binding would emit a depwarn to stderr on every metadata write. Optional
guard:
Base.isdeprecated(mod, name) && continue. Low priority.

6. _deserialize_relaxation_filter else → relax_filter_all silently

src/FLOWPanel_replay.jl:677-678. Same silent-substitution class as #1, lower stakes
(filter is
niche). Warn for consistency with the plan's principle.

7. Cosmetic: manual prefix slicing

src/FLOWPanel_replay.jl:166 uses tag[lastindex(prefix)+1:end]; the plan specified
chopprefix(tag, "FLOWVPM."), which is clearer and index-arithmetic-free.

Streamlining assessment (the "avoid large lists" ask)

Honest split of the remaining hand-maintained chains:

- Pure singletons → fully reflectable, no list needed. SFS is done. The relaxation
method
function (#2) is the one remaining case and should be converted. After that, every
genuine
singleton in the metadata is list-free.
- Parameterized constructors → the lists are load-bearing; keep them.
_viscous_manifest,
_wake_shedding_manifest, _particle_policy_manifest, _monitor_normalization_metadata,
_monitor_metadata, _backend_metadata_dict, _solver_metadata_dict reconstruct via
constructors that need per-type argument knowledge (positional vs keyword; {Float64}
type
params; opaque fields like SplitParticles.opts). A generic "reflect fieldnames → call
the
constructor" scheme would be fragile and is not robust. For these, the correct
robustness fix is
not to delete the list but to make every deserialize else loud (finish #1 and #6) so
a
missing entry is never a silent physical substitution. Several of them
(backend/solver/monitor/
normalization) are already record-only on the read side, so they carry no
silent-substitution
risk at all.

Net: the streamlining is targeted (reflect the relaxation function), not a wholesale
reflection
rewrite. Trying to reflect the parameterized constructors would trade a clear
enumerated list for a
fragile generic path — the opposite of "remaining robust."

(Optional, not recommended now: route parameterized types through multiple dispatch
on the
reflected type — T = _resolve_singleton(tag, Type); _construct(T, meta) with one
_construct
method per type. This makes the method table the registry instead of a string ==
chain, but keeps
identical per-type constructor knowledge. Only worth it if the number of types grows
substantially.)

Plan

All changes in src/FLOWPanel_replay.jl, with matching test additions in
test/runtests_unit_replay.jl.

1. Reflect the relaxation method function (#2). In _relaxation_manifest, keep the
nsteps_relax < 0 → "none" branch first (its relax is an anonymous closure,
un-nameable), then
replace the two hardcoded function branches with t = _singleton_tag(FLOWVPM,
relaxation.relax);
fall back to _metadata_unsupported_dict only if t === nothing. In
_deserialize_relaxation,
keep the "none" branch, then replace the two string branches with
_resolve_singleton(rtype, Function) and pass the resolved function to
FLOWVPM.Relaxation(fn, nsteps, rlxf, filter).
2. Make the relaxation else loud (#1). Only reachable now for a genuinely
unresolvable tag;
@warn "replay: unrecognized relaxation tag \"$(rtype)\"; falling back to
correctedpedrizzetti (result may differ)" before the default (or let
_resolve_singleton throw for a bad tag and
reserve the warn+default for the "unsupported"/missing case, matching
_deserialize_sfs).
3. Warn in _deserialize_relaxation_filter else (#6).
4. Fix migration pollution (#3). In migrate_metadata_toml, only touch pfield_optargs
when
a legacy viscous/SFS/relaxation key is actually present on the wake entry (or gate on
get(wmeta, "type", "") == "PanelParticleWake"), so untouched wakes stay
byte-identical.
5. Cosmetic/hardening (#4, #5, #7): switch to chopprefix; add the Base.isdeprecated
skip in
_singleton_tag; add a one-line comment noting _resolve_singleton is FLOWVPM-scoped by
design.
