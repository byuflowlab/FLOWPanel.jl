# Plan: Close remaining reproduction-metadata gaps in FLOWPanel replay serialization

*Standalone plan — written for an agent with no prior context. All file paths are relative to the
repo root `/Users/ryan/Dropbox/research/projects/FLOWPanel.jl`.*

---

## Context

FLOWPanel writes a `<run>.metadata.toml` restart/replay manifest during `simulate!` so a run can be
reproduced. A prior change added the particle **relaxation scheme** to this manifest (it was being
silently inherited from FLOWVPM's `ParticleField` default, `relax_correctedpedrizzetti`). A sweep of
the remaining serializers found more settings that are either **silently reconstructed to a wrong
default** (the dangerous class — same bug pattern as relaxation) or **emitted only as an
`unsupported` marker** (safe-ish: self-flags, but not reproducible).

The serialize/deserialize code lives in two files:
- **Serializers** (manifest dicts): `src/FLOWPanel_replay.jl` — `_sfs_manifest`, `_viscous_manifest`,
  `_particle_policy_manifest`, `_relaxation_manifest`, `_vpm_optarg_manifest`; and
  `src/FLOWPanel_metadata.jl` — `_monitor_metadata`.
- **Deserializers** (reconstruction): `src/FLOWPanel_replay.jl` — `_deserialize_sfs`,
  `_deserialize_viscous`, `_deserialize_particle_policy`.

Every unhandled type currently routes to `_metadata_unsupported_dict` (serialize) or a hard-coded
default (deserialize). The goal is to extend the type coverage so real configurations round-trip.
Follow the existing relaxation implementation as the reference pattern (identity/type check on
serialize, tag string → constructor on deserialize, plus a round-trip unit test).

Do **not** hand-edit any existing `data/**/*.metadata.toml`; only change the (de)serialization code
so future runs self-document. Existing files still load via the graceful fallbacks.

## Category A — silent wrong-default on reconstruction (HIGH priority)

These currently deserialize to a default when the type isn't recognized, silently discarding the
real setting. Same failure class as the relaxation default. Fix both serialize and deserialize.

### A1. SFS (sub-filter-scale) schemes
Only `SFS_default` and `SFS_Cd_twolevel_nobackscatter` are recognized today. FLOWVPM defines these
named singletons (`../FLOWVPM.jl/src/FLOWVPM.jl:222-278`), all of which should round-trip by identity:
- `SFS_none` (note: `SFS_default === SFS_none`, same object — treat as one canonical tag)
- `SFS_Cs_nobackscatter`
- `SFS_Cd_twolevel_nobackscatter`
- `SFS_Cd_twolevel_nobackscatter_projection`
- `SFS_Cd_twolevel_backscatter_signed`
- `SFS_Cd_threelevel_nobackscatter`

Changes:
- `_sfs_manifest` (`src/FLOWPanel_replay.jl`): add an identity check (`sfs === FLOWVPM.SFS_x`) for
  each singleton returning `Dict("type" => "FLOWVPM.SFS_x")`. Because `SFS_default === SFS_none`,
  emit a single canonical tag (recommend `"FLOWVPM.SFS_none"`) and keep accepting the legacy
  `"FLOWVPM.SFS_default"` tag on read.
- `_deserialize_sfs` (`src/FLOWPanel_replay.jl:537`): add each tag → the corresponding
  `FLOWVPM.SFS_x` constant. Keep the existing fallback to `SFS_default`.
- Simplify `_vpm_optarg_manifest` (added in the relaxation change): it currently hard-codes an
  identity list for `SFS_default`/`SFS_Cd_twolevel_nobackscatter`. Replace that with a dispatch
  `_vpm_optarg_manifest(val::FLOWVPM.SubFilterScale) = _sfs_manifest(val)` so SFS coverage lives in
  one place. (`SubFilterScale{R}` is the abstract supertype, `../FLOWVPM.jl/src/FLOWVPM_subfilterscale.jl:89`.)

### A2. Viscous schemes
Only `Inviscid` and `CoreSpreading` are handled; `ParticleStrengthExchange` silently reconstructs as
`Inviscid`. `ParticleStrengthExchange{R}` fields (`../FLOWVPM.jl/src/FLOWVPM_viscous.jl:231`): `nu::R`,
`recalculate_vols::Bool`; constructor `ParticleStrengthExchange{R}(nu; recalculate_vols=true)`.

Changes:
- `_viscous_manifest` (`src/FLOWPanel_replay.jl`): add a branch →
  `Dict("type" => "FLOWVPM.ParticleStrengthExchange", "nu" => v.nu, "recalculate_vols" => v.recalculate_vols)`.
- `_deserialize_viscous` (`src/FLOWPanel_replay.jl:517`): add the matching tag →
  `FLOWVPM.ParticleStrengthExchange{Float64}(nu; recalculate_vols=...)`.

## Category B — currently emitted as `unsupported` marker (MEDIUM priority)

These self-flag (`restart_reconstruct_required = true`) rather than silently corrupting, but are not
reproducible. Serializer `_particle_policy_manifest` and deserializer `_deserialize_particle_policy`
are both in `src/FLOWPanel_replay.jl` (deserializer at `:478`).

### B1. `RelativeMinGamma` trim policy
`struct RelativeMinGamma{T}` field `fraction::T` (`src/FLOWPanel_wake.jl:689`), constructor
`RelativeMinGamma(fraction)`. Add:
- `_particle_policy_manifest`: `Dict("type" => "RelativeMinGamma", "fraction" => policy.fraction)`.
- `_deserialize_particle_policy`: `"RelativeMinGamma"` → `RelativeMinGamma(Float64(get(meta,"fraction",0.0)))`.

### B2. `SplitParticles` functional policy — PARTIAL
`struct SplitParticles{TO}` fields `every::Int`, `opts::TO`, `verbose::Bool`
(`src/FLOWPanel_wake.jl:772`). `opts` is an opaque options object (type-parameterized, not a simple
scalar) — full round-trip is out of scope. Recommended: serialize the scalar fields
(`every`, `verbose`) and mark `opts` unsupported, e.g.
`Dict("type" => "SplitParticles", "every" => p.every, "verbose" => p.verbose,
"opts" => _metadata_unsupported_dict(typeof(p.opts)))`; on deserialize, if `opts` is unsupported,
skip reconstruction (return `nothing`, consistent with the existing filter in
`_deserialize_particle_maintenance` at `:512-513`). Document this partial coverage in a comment.

### B-note. `Prepared*` runtime variants need no handling
`PreparedRelativeMinGamma` / `PreparedFrameBox` (`src/FLOWPanel_wake.jl:699,751`) are produced at
runtime by `prepare_particle_policy` during `simulate!`. The wake manifest serializes the *original*
`wake.particle_maintenance` policy tuple (unprepared), so these never reach the serializer. No action;
add a one-line comment noting this so a future reader doesn't add dead branches.

## Category C — record-only monitor coverage (LOW priority)

Monitors are **not reconstructed** from metadata (`replay(...)` takes `monitors=()` from the caller,
`src/FLOWPanel_replay.jl:800`); `_monitor_metadata` in `src/FLOWPanel_metadata.jl` is record-only.
All monitor types are covered except `CylindricalFieldProbeMonitor`
(`src/FLOWPanel_simulate_monitors_fieldprobe.jl:23`), which falls to the unsupported marker.

Change (`_monitor_metadata`, `src/FLOWPanel_metadata.jl`): add a branch recording the scalar config
fields: `i_frame`, `axial_axis` (Symbol → string), `n_axial`, `n_radial`, `n_azimuth`, `save_path`
(handle `nothing`), `name`, `verbose`. (`axial_range`/`radial_range` are not stored as fields — they
are baked into `positions_local` — so they cannot be recovered; acceptable for record-only.)
