## Purpose

Isolate, with high confidence, the precise cause of the anomalous **tip** bound circulation
in the Phase 2c capped/Dirichlet DJI solves, and decide whether it is a fixable
mesh/geometry issue or an inherent Morino/numerical sensitivity — so the DJI Dir–Neu gap
conclusion rests on trustworthy tip data.

**Why this matters (end goal, Ryan 2026-07-24):** the **Dirichlet formulation is the
production path** for modeling the DJI rotor — this study verifies that Dirichlet converges
to the right answer and determines the mesh resolution/settings required. A later run with
Green reconstruction of the wake-induced potential (Phase 4) is expected to close much of
the experimental gap. Neumann is the reference oracle only and cannot be substituted, so
Phase 2d's deliverable is not just attribution: it is the **mesh/settings prescription under
which Dirichlet tip circulation is trustworthy**.

**Scope (re-scoped after review, 2026-07-24):** **A and C are the required core** (A
localizes the anomaly and decomposes μ; C tests H5, the one hypothesis whose confirmation
yields a generally valuable code fix). B is nearly free — keep it. **D and E are
conditional: run them only if A+C leave the cause ambiguous**, and stop to reassess with
Ryan before starting them.

**Success criterion (Ryan, 2026-07-24): diagnosis alone is NOT success.** If a study
identifies an issue, this phase must also seek and implement the solution — **modifying
source code is in scope** (with the unit tests named under Verification); **targeted
changes (e.g. panel-relative regularization) may proceed directly, but if the solution
requires a major code overhaul, stop and get Ryan's permission before pursuing it**.
Phase 2d is
complete only when a **converged Dirichlet solution and the settings that produce it are
demonstrated** (step F below): tip Γ physical (Dirichlet approaching Neumann from below)
and monotonic across the ladder, and the Dir–Neu circulation gap meeting the study's ≤1%
criterion under refinement — generating finer/intermediate meshes with
`generate_dji9443_mesh.sh` if the existing ladder is insufficient.

## Context (the observation)

Phase 2c's extended chordwise ladder (45 spanwise; n_airfoil ∈ {145,185,201,249};
capped/Dirichlet Morino source+doublet vs uncapped/Neumann vortex-ring) found the Dirichlet
bound circulation near the blade tip (r/R ≳ 0.9) is **non-monotonic in n_airfoil** and
partly **non-physical**:

| n_airfoil | Dir Γ_TE @ r/R≈0.95 | outboard Dir–Neu gap | vs Neumann tip (~0.143) |
|---:|---:|---:|---|
| 145 | 0.1384 | +2.55% | below (expected) |
| 185 | 0.1534 | +0.30% | **overshoots** |
| 201 | 0.1539 | +0.28% | **overshoots** |
| 249 | 0.1391 | +2.41% | below (expected) |

The uncapped/Neumann tip is identical across all four meshes. This tip artifact made the
Phase 2c outboard gap falsely appear "converged" (~0.28%) at 185/201; the honest,
interior-governed gap is ~2.2% and still decreasing (see the Phase 2c extended report). The
tip caps were **generated by an identical recipe for all four meshes** (per Ryan), so this
is NOT two cap recipes: an identical-recipe cap whose triangle count scales smoothly
(282/360/389/484) nonetheless yields non-monotonic, physically-wrong (Dir > Neu) tip
circulation at 185/201.

## What we already know (read-only analysis already done — do NOT redo)

Driver `examples/dji9443_mesh_convergence.jl`; meshes
`examples/data/dji9443_20260723_45_{145,185,201,249}_{capped,uncapped}.msh`. Hypotheses
ELIMINATED empirically:

1. **grad_mu basis** — bit-identical Γ for dji45_145 under default `:quad` vs
   `grad_mu_options=(basis=:tri, tri_robust=true)` (Γ_TE = μ-jump is grad_mu-independent).
2. **TE triangle-pair orientation → misaligned upper/lower control points** — control points
   are plain centroids (`calc_controlpoints!`, `src/FLOWPanel_abstractbody.jl:772`, no
   offset); paired upper/lower TE centroids are chordwise-aligned to ~4e-6 m, identically in
   145c and 185c.
3. **TE pairing / single-sided tip (`pj==-1`)** — all 44 sections paired in both meshes.
4. **Watertightness** — all capped meshes `iswatertight == true`.
5. **Cap normal winding flip** — every +y tip-cap normal is outward in all four meshes.
6. **Degenerate/sliver caps** — no NaN normals; cap aspect ratio median 1.6–2.0, max ≤5.
7. **Two cap recipes** — ruled out by Ryan (identical recipe).

**Established:** the tip TE *extraction* geometry is essentially identical between a "low"
(145) and "high" (185) mesh → the ~10% tip-Γ difference is a **genuine difference in the
solved Morino doublet field near the tip**, capped/Dirichlet-only, invisible to first-order
geometry metrics, and non-monotonic under an identical cap recipe.

## Hypotheses (open)

- **H1 — Cap↔surface seam / sharp-tip-TE-corner interaction.** With one recipe, the local
  arrangement where the cap meets the sharp trailing edge and the last airfoil station still
  varies with n_airfoil; a configuration at 185/201 perturbs the Morino tip solution.
- **H2 — Which quantity carries the overshoot** (μ_upper, μ_lower, or the cap doublet
  strengths) — unknown until the solved field is dumped.
- **H3 — Inherent Morino / (I−B) tip sensitivity or conditioning.** The capped Dirichlet
  system has a known near-null constant mode (Phase 2b prior evidence); a
  resolution-dependent tip mode / worse conditioning at 185/201 could inflate the tip
  doublet. Check solve residual, matrix conditioning, near-null spectrum per mesh.
- **H4 — Which group is correct.** 185/201 overshoot Neumann (non-physical for
  Dir-converging-from-below), so 145/249 are probably the trustworthy group; confirm.
- **H5 — Fixed regularization radius vs shrinking / high-aspect-ratio tip panels.** The
  driver uses a FIXED regularization (`kerneloffset_panel = R*1e-10`, `kernelcutoff =
  R*1e-13`, `kerneloffset_targets = 1e-3`; constants in the driver), applied as `core_size`
  in the induced kernels (`src/FLOWPanel_elements_fmm.jl` `_induced`/`regularize` ~`:796,939`)
  and the panel-panel `(I−B)` assembly (`_G!`, `src/FLOWPanel_formulation.jl:448,466,476`).
  It is **not scaled by panel characteristic length**, so as n_airfoil rises and tip panels
  shrink — with the thin tip putting upper/lower surface panels very close, possibly at high
  aspect ratio — the regularization's relative role changes and could act non-monotonically.
  (Phase 2 found `kerneloffset_panel` "inert" for integrated CT, but never probed tip-local
  circulation, and did not sweep at these fine tip resolutions.)

## Mesh generation tool (new capability)

**`scripts/generate_dji9443_mesh.sh`** lets the agent generate additional DJI 9443 meshes
from the command line (usage in the script header; `--help` for options): positional
`SPANWISE CHORDWISE ROOT_CAP TIP_CAP [CAP_TESS]`, cap modes `none|flat|round` per end
(the Phase 2c `capped` meshes = **flat root + round tip, CapUMinTess=3** — this documents
the "identical cap recipe" concretely, closing the former open item). CHORDWISE must be
odd. Runs locally on Ryan's Mac (needs OpenVSP + gmsh); `scp` outputs to the cluster if a
solve needs HPC. This makes controlled tip-treatment variants (e.g. `flat` tip cap, or a
different `--cap-tess`) a one-command step — see E2.

## Experiments (cheap→expensive; each isolates one thing)

### A. (CORE) Instrumented solve — localize *where* the field differs (145c vs 185c)  [decisive for H2, H4, and confirms field-vs-extraction]
Add a diagnostic recording path to the driver (a new `PHASE2C_MODE`, e.g. `tipdiag`, or a
sibling script; do NOT change default `solve`/`extend` behavior). For a given capped tag,
solve as usual and dump:
- per-panel solved doublet strength `body.strength[:, i_strength]` with panel centroid and a
  region tag {surface, cap, teU, teL} (identify cap panels via centroid |y|/R>0.97 &
  |normal_y|>0.5, as in the pre-work; teU/teL from the `shedding` columns);
- per TE section the **separate** μ_upper=`strength[pi]` and μ_lower=`strength[pj]` (today
  only their difference is saved by `write_raw`);
- the monitor's `circulation_slice` (extraction-independent) beside `circulation_te`;
- the Morino solve residual and an `(I−B)` conditioning estimate.
Reuse `BoundCirculationMonitor` / `_bound_circulation_slice`
(`src/FLOWPanel_simulate_monitors.jl:2337,2313`). Compare 145c vs 185c:
- Does `circulation_slice` also show the 185 tip overshoot? → **yes ⇒ solved field, not
  extraction** (confirms the pre-work; no ⇒ re-open extraction).
- Is the overshoot in μ_upper, μ_lower, or the **cap** doublet strengths? → says whether cap
  panels or surface panels are anomalous.
Compute: 145c fits locally (27608 panels, ~6 GB, ~7 min). **185c is 35288 panels (~10 GB
dense) — borderline on the 17 GB laptop; prefer HPC** (BYU `orc`, per `agent_policies/HPC.md`

`examples/run_dji9443_mesh_convergence_hpc.slurm.sh`).

### B. (cheap — keep) Geometry & conditioning diff of the tip-corner  [H1, H3, H5]  (read-only + light)
For 145c vs 185c (and 201c vs 249c to probe the split): extract the r/R>0.9 sub-mesh; at the
tip-most corner where the sharp TE meets the radial cap, compare connectivity (cap triangles
per last-TE node; fan-vs-grid), the last few section quad diagonal patterns, and the exact
cap↔surface seam, using `calc_neighbors` (`src/FLOWPanel_abstractbody.jl:215`),
`_calc_edge_to_cells` (`:153`), `_component_orientation_score` (`:251`). Also measure the tip
**surface** panel aspect ratios and the upper–lower panel gap vs panel size (for H5). Export
the tip sub-mesh to VTK for ParaView. Goal: a concrete topological/geometric invariant (if
any) that splits {145,249} from {185,201}; if none, that strengthens H3/H5 (numerical/
regularization sensitivity, not geometry).

### C. (CORE) Regularization sensitivity sweep  [H5]  (targeted)
On 185c (the clearest anomalous mesh; HPC if needed), re-solve with a sweep of
`kerneloffset_panel` and `kernelcutoff` — e.g. 0, the current `R*1e-10`, a **panel-relative**
value (`k · characteristiclength`), and a larger fixed value — holding everything else
fixed, and read the tip Γ each time. **If the tip overshoot moves with the offset, H5 is the
lever** (and the fix is to scale regularization with panel size). If the tip Γ is inert to
the offset (as Phase 2 saw for CT), H5 is out. Cheap variant first: reuse the existing
145c/185c solves' geometry and only vary the offset. **If H5 confirms, follow through:**
verify that a panel-relative regularization restores tip monotonicity across the
{145,185,201,249} ladder — that setting becomes part of the production Dirichlet
configuration handed to Phase 5.

### D. (CONDITIONAL — only if A+C leave the cause ambiguous) Controlled reproduction on a simple validation case  [H1 vs H3 vs H5]
Use the capped rectangular oracle in `examples/pitching_wing.jl` (`pitching_wing_mesh(...;
caps, thickness)`, added in Phase 2b; driven by
`examples/dji9443_formulation_attribution.jl` `oracle` mode), which solves Dirichlet (capped)
vs Neumann (open) on identical lifting-surface coordinates through a matched wake. Sweep its
**chordwise resolution** (analogue of n_airfoil) with the identical cap recipe and a sharp
tip, and watch the tip bound circulation vs the Neumann reference. **Success = the simple
wing reproduces a non-monotonic tip-Γ overshoot (Dir > Neu) with a single cap recipe** — this
proves the mechanism is generic (H3/H5), not a DJI mesh defect, and is cheap (small mesh,
seconds/solve). First verify pitching_wing builds a sharp-TE capped tip; if too idealized,
build a minimal standalone sharp-TE capped wing/box as the validation case.

### E. (CONDITIONAL — only if A+C leave the cause ambiguous) Causal confirmation on the DJI meshes  [gold standard]
Change ONLY the tip region on one mesh and show the tip Γ moves between groups:
- **E1 — in-repo tip re-mesh:** on 185c, re-triangulate just the tip-corner/cap opening in
  the 145c pattern (surface nodes at the opening are shared; only the tip fill changes),

- **E2 — agent-generated control meshes (likely easier than E1):** use
  `scripts/generate_dji9443_mesh.sh` (see the tool section above) to generate controls

  pair at two n_airfoil values — cleanly separating tip-cap geometry from chordwise
  resolution. Generate locally, `scp` to the cluster for the solve if needed. Fall back to
  Ryan-generated controls only if the script cannot produce the needed variant.

## Decision rule & deliverables

Because Dirichlet is the production formulation (see Purpose), every outcome is a **fix
path that must end implemented and verified via step F** — not handed off as a
recommendation: **(i) fixable tip-corner/seam geometry** → regenerate correct-tip meshes
(expressible as `generate_dji9443_mesh.sh` arguments — likely the {145,249} pattern, which
undershoots Neumann as expected), re-run the ladder, verify F's criteria; **(ii)
fixed-regularization artifact** (H5) → implement panel-size-scaled regularization in
`src/`, run the named unit tests, re-run the ladder, verify F's criteria — that setting
becomes production; **(iii) inherent Morino tip sensitivity/conditioning** — only if the
cause is proven inherent and unfixable — is the **last-resort fallback**, and even then the
phase must demonstrate a converged configuration within the trustworthy family (e.g.
145/249-pattern meshes, extended with the script), not merely document the pathology, so
Phase 5 has a defensible production configuration.

Deliverables under `data/dji_convergence_20260722/phase_02d_tip_cap_discrepancy/`: tip μ
dumps, `circulation_slice` vs `circulation_te`, conditioning numbers, tip-geometry diff,
regularization sweep, oracle reproduction; a `phase_02d_report.md`; and an updated pointer in
the Phase 2c conclusion. Write the decision into the Phase 2d log snapshot + the dashboard
Progress line, then **stop for Ryan's approval** before Phase 3.
