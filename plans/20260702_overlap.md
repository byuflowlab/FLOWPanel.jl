## 1. Problem statement and goal

FLOWPanel's particle wakes represent vorticity as `ω(x) = Σ_i Γ_i ζ_{σ_i}(x−X_i)` with normalized
Gaussian kernels. The live FLOWVPM update advances each `Γ_i` with a **single-particle** stretching
rule, which is only consistent with the filtered vorticity transport equation when particle supports
do not overlap. Item 008 derived the overlap-aware system

```
M Γ̇ = b
```

where `M` is a scalar kernel-overlap matrix (applied identically to the 3 vector components) and `b`
is the projected filtered-vorticity RHS. A completed collocation diagnostic (results recorded in the
brainstorm doc, 2026-06-24 section) found the live update sits at a **stable ~62% relative
field-space residual** (sampled fvpm residual ≈ 0.62) from the overlap-projected RHS on settled
rotor-hover states — a GO for building an actual solve.

**User's ask for this phase:**
1. Find a *robust* way to solve the overlap-aware DΓ/Dt system.
2. First steps: use existing simulation data, isolate a small portion, examine properties of the
   overlap-aware system including its **condition number**.
3. Analyze how close **Pedrizzetti relaxation (vanilla and corrected, at several rlxf values)**
   comes to satisfying the overlap equations.
4. New simulations only if needed (they are not — see §4); escalate to a workstation if local
   compute becomes prohibitive (criteria in §10).

**User's solve-strategy decision:** matrix-free CG is the practical long-term approach, but an
explicit Gram-matrix linear solve is the preferred *first* step because it is more likely to
succeed. Solve ladder: (1) dense Cholesky on subsystems up to np≈8000 (exact, guaranteed — this
is the explicit-Gram entry point), (2) matrix-free Jacobi-PCG at full scale, validated against
(1) on the largest subsystem, (3) explicit *full-scale* Gram assembly + Cholesky only as a
workstation fallback if (2) fails validation — the local machine has 16 GB RAM (verified via
`hw.memsize`) and cannot hold the ~12.4 GB full matrix plus factorization workspace.

**User's pacing decision:** run all stages straight through without checkpointing; only stop on
gate failures or workstation-scale cost.

## 4. The Galerkin system (what gets solved)

Test functions = the particle kernels themselves. For normalized Gaussians the Gram matrix is
analytic:

```
M_G[k,i] = ∫ ζ_{σ_k}(x−X_k) ζ_{σ_i}(x−X_i) dx
         = zeta_sigma(|X_k−X_i|², sqrt(σ_k²+σ_i²))          (same zeta_sigma as POR)
M_G[i,i] = ζ0 / (2√2 σ_i³)
```

Symmetric, and SPD when the active kernels are numerically independent. The system is
`M_G Γ̇^(a) = b_G^(a)` for components a = 1,2,3 (scalar matrix, 3 RHS columns).

**Galerkin RHS — midpoint particle quadrature.** The exact `∫ζ_k·RHS dx` is O(N³) (RHS is quadratic
in the basis). Beware the degenerate shortcut `b_G = M_G·s` (s = center-sampled RHS): CG would
return exactly `Γ̇ = s`, learning nothing. Use volume-weighted midpoint quadrature at particle
centers:

```
b_G[k,:] = Σ_i vol_i · zeta_sigma(|X_i−X_k|², σ_k) · RHS(X_i)
```

(the quadrature kernel is the *test* function ζ_{σ_k} evaluated at nodes — width σ_k, not the
pairwise width). `RHS(X_i)` is the same sampled field RHS the collocation diagnostic builds:
`S(J_i, ω_basis(X_i)) − c_i` where `ω_basis = MΓ` (collocation mat-vec with V=Γ), `S` is either
`s_phys` or `s_fvpm` (report the fvpm flavor as the headline, physical as secondary), and `c_i` is
the convective-basis correction. Label this in code and doc as "O(h²) midpoint quadrature of the
Galerkin projection; exact in the no-overlap limit."

**Quadrature-error gate:** apply the identical quadrature rule to the Gram itself,
`Q[k,i] = Σ_j vol_j ζ_k(X_j) ζ_i(X_j)`, on a Part-1 sub-cloud; report `‖Q−M_G‖_F/‖M_G‖_F` as the
**error floor** — never interpret Galerkin residuals below that floor. Also report the
partition-of-unity calibration `Σ_i vol_i ζ_k(X_i)` (should ≈ `∫ζ_k = 1`; report its
distribution over k) as a cheap second calibration of the same quadrature.

**Floor interpretation (important):** quadrature nodes are *forced* to particle centers — `J`
and `velocity` are only known there — so a large floor cannot be refined away by adding nodes.
That does NOT invalidate the study: `Γ̇⁽⁰⁾`, the Galerkin solve, and every Pedrizzetti variant
are all scored against the *same* `b_G`, so their ordering and residual-reduction factors remain
meaningful regardless of quadrature bias. Only *absolute* claims ("the residual is X% of the true
field residual") are floor-limited; label them as such in the writeup.

## 5. Residual metrics (identical definitions everywhere)

For any candidate rate `Γ̇` (3×np), ε = 1e-30:

1. **Galerkin residual** `r_G(Γ̇) = ‖M_G Γ̇ᵀ − b_G‖_F / (‖b_G‖_F + ε)` — primary metric.
2. **Collocation sampled residual** — the existing `analyze` sampled residual with `Γ̇` substituted
   for the isolated rate (continuity with the recorded 0.62 baseline).
3. **Correction size** `‖Γ̇ − Γ̇⁽⁰⁾‖_F / (‖Γ̇⁽⁰⁾‖_F + ε)` with `Γ̇⁽⁰⁾_i = s_fvpm(J_i, Γ_i)`
   (plus SFS term `−C_i·SFS_i·σ_i³/ζ0` when SFS is included).
4. **Correction alignment** (Part 3): with `Δ_x = Γ̇_x − Γ̇⁽⁰⁾`, report `cos∠(Δ_x, Δ_ref)` and
   captured fraction `α* = ⟨Δ_x, Δ_ref⟩ / ‖Δ_ref‖²` (Frobenius inner products over all particles),
   where `Δ_ref` comes from the Galerkin solve. Also per-particle distributions.

Two conventions that apply everywhere:
- **Subsystem metrics are interior-only.** Every residual/alignment metric computed on a
  subsystem is evaluated over the interior set I only — buffer particles are boundary-condition
  carriers whose Δ is biased toward `Γ̇⁽⁰⁾` by construction.
- **Headline "before" number.** The full-scale `r_G(Γ̇⁽⁰⁾)` supersedes the recorded 0.62
  collocation figure as the baseline residual of the live update; the collocation sampled
  residual is kept only for continuity with the 2026-06-24 diagnostic.

## 8. Part 3 — Pedrizzetti closeness

**New file:** `examples/particle_pedrizzetti_vs_galerkin.jl`.

  `Γ̇*_sub`** from Part 1 (np=8000 buffered interior, interior particles only). Note `b_G` must

- **Part 3b (after Part 2):** recompute cos∠/α* against the full-scale `Γ̇*`/`Γ̇^CG` as

**Exact offline replay** per state/variant from saved `(X, Γ, σ, J, SFS, C)` and confirmed `dt`:
1. `Γ⁺` = sequential in-place transposed stretching exactly as `_euler` (see §3 — G[2] uses updated
   G[1], G[3] uses updated G[1],G[2]).
2. `Γ⁺ .-= dt·C_i·SFS_i·σ_i³/ζ0`.
3. `Γ⁺⁺ = relax(Γ⁺)` with ω from the same pre-step J; vanilla and corrected re-implemented

   exactly as written.
4. `Γ̇_eff = (Γ⁺⁺ − Γ)/dt`.

**Grid:** rlxf ∈ {0, 0.06, 0.3, 0.6, 1.0} × {vanilla, corrected}. rlxf=0 must equal `Γ̇⁽⁰⁾+SFS`
exactly (consistency check; both variants collapse).

log / `examples/rotor_hover_pressure_comparison.jl` that `nsteps_relax=1` (relaxation applied
every step) — if relaxation is periodic, gate only on the applicable steps.

**Metrics per variant** — all against the SAME (SFS-on) `b_G`; alignment against `Γ̇*_sub`
(Part 3a) and then the full-scale `Γ̇*`/`Γ̇^CG` (Part 3b):
- `r_G(Γ̇_eff)` (one Galerkin mat-vec each; ~10 variants ≈ 6 min/state matrix-free).
- Collocation sampled residual of `Γ̇_eff`.
- `‖Γ̇_eff − Γ̇*‖_F/‖Γ̇*‖_F`, per-particle angle and magnitude-ratio distributions.
- **Key answer:** `cos∠(Δ_relax, Δ_solve)` and captured fraction `α*` (§5.4). α* ≈ 0 or negative ⇒
  relaxation does not move toward the overlap-consistent solution; meaningfully positive and rising
  with rlxf ⇒ relaxation is a crude proxy, and the best (variant, rlxf) is reported.
- **Optimal-scaling metric (direction test, decoupled from rlxf/dt):** for each variant's
  correction direction `Δ_relax = Γ̇_eff − Γ̇⁽⁰⁾`, compute the Galerkin-norm optimal step

  ```
  s* = ⟨M_G Δ_relax, b_G − M_G Γ̇⁽⁰⁾⟩ / ‖M_G Δ_relax‖²      (Frobenius inner products)
  ```

  and report `r_G(Γ̇⁽⁰⁾ + s*·Δ_relax)` (two mat-vecs per variant). This answers "is the
  relaxation *direction* useful at any strength?" independently of the rlxf grid and the dt
  scaling — it is the cleanest single number for the viable-alternative question.
- Monotonicity: does r_G(Γ̇_eff) decrease with rlxf, and where does it land between r_G(Γ̇⁽⁰⁾) and
  r_G(Γ̇*)? (The r_G(Γ̇*) endpoint uses the subsystem solve in Part 3a; finalized in Part 3b.)
- Report caveat: relaxation is a Γ-space projection, so Γ̇_eff scales with rlxf/dt — conclusions
  are dt-specific (rlxf 0.3 at this dt ≈ effective rate ~10³ s⁻¹).

## 9. Part 4 — Robustness levers and the acceptance definition

- λ choice: smallest λ from the Part-1 sweep giving Jacobi-preconditioned cond ≲ 10³ with solution
  drift < 5%; fixed a priori, not per-state. (This decision stays in Part 1 where it's needed.)
- **The two probes below run only if the Part-2/3 verdict is GO** — they inform a *live*
  implementation design, not the solvability/viability questions:
  - Truncation sensitivity at full scale: `‖(M^{c=3} − M^{c=5})v‖/‖M^{c=5}v‖` on a random v and on
    Γ̇⁽⁰⁾ (two extra mat-vecs); accept the cheaper cutoff if < 1e-3.
  - Locality probe: buffered-interior solution `x_I` vs buffer width n_buf ∈ {2√2, 4√2, 6√2}·σ. If
    x_I converges by 4√2, the overlap solve is effectively local ⇒ a cheap domain-decomposed live
    update is plausible; record either way.
- **"Robust" (to be written into the doc verbatim):** the solve is robust if PCG converges
  monotonically to `r_G ≤ max(0.1, 2× quadrature-error floor)` in ≤150 iterations across all tested
  states and both Part-1 regions' conditioning regimes, with one a-priori λ, a coherent correction
  (Part-2 criteria), and cutoff-insensitivity (<1e-3 between 3 and 5 σ_eff). If per-state tuning is
  required, report "not robust — pivot."
