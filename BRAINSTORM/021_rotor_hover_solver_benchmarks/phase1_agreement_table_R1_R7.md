# BRAINSTORM 021 — Phase 1 solution agreement, R1–R7

Harvested 2026-08-28 from `benchmark/results/phase1/multi/agreement{,_spread}_merged.csv`
(regenerated by `benchmark/p021_merge.jl`; Phase 1 portion merged clean — **no
duplicate rows**). NB this is a no-duplicates guarantee, *not* a completeness one:
`p021_merge.jl` builds its expectation from the pairs it observes and only reports a
missing config when `CONFIGS` is set in the environment, which the §3 harvest recipe
does not set (and a single `CONFIGS` list could not express this campaign's per-rung
expectation anyway, since the roster shrinks with rung). Completeness was therefore
verified separately, 2026-09-05, directly against `agreement_merged.csv`: expected
roster per rung is the full 7 at R1–R4, minus the two dense `backslash_*` configs at
R5–R6, minus `krylov_jacobi` additionally at R7 — **observed exactly, with no missing,
extra, or duplicated config at any rung**. R1 additionally carries two
`residual_backend=direct` rows (`fgs`, `krylov_gmres`) for the O(N²) cross-check of
Table 3; these are excluded from Table 2 and from the ensemble statistics.

**R7 `CT_laplace` is not a usable number** and must not be published as one.
All four R7 configs agree on it to 3.4e-5 **absolute** — which on a value of
−0.0015 is **2.3% relative**, not the ~1e-5 relative tightness the relL2 figures
elsewhere in this document report. The spread is also entirely `krylov_gmres`
(−0.00146254 against −0.00149643 / −0.00149561 / −0.00149636, which agree among
themselves to 8e-7). The common-mode conclusion stands regardless: every solver
reproduces the same collapsed value to well within the gap to the ~0.062 trend, so the
solve is consistent and the Laplace pressure recovery is not. `CT_bernoulli` and `CT_kj`
both sit exactly on their R1→R6 trends at R7, which localises the defect to
`PressureLaplace` on the R7 mesh — not to the solver, the wake, or the shedding.
Cause not yet investigated.
