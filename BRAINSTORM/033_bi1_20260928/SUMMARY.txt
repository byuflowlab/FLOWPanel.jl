ANOMALIES & CAVEATS
================================================================================

1. PASS COUNT MISMATCH (old=3, new=1): Expected behavior
   - Old setup: 3 functional passes (warmup pass 0 + production passes 1-3)
   - New setup: 1 construction pass (pass=1)
   - Difference reflects different benchmarking intent: old tests kernel stability
     across iterations; new tests initialization cost once

2. R4 j1 INCOMPLETE: Run terminated or file truncated after old setup warmup
   - Only 6 rows (warmup + 2 production phases) before stopping
   - New setup data: missing (setup_threads not applied)
   - Cert data: absent
   - Impact: Cannot validate j1 sanity check (serial code should be invariant)

3. GC BYTES LARGE: R5_j64 old setup peaks at 11.8 GB
   - R4_j64 old: 5.1 GB (warmup)
   - R5_j64 old: 12.1 GB (warmup), 11.8 GB (production)
   - Cause: FMM tree construction + kernel cache allocation at larger scale
   - Not a concern (well within system memory)

4. PHASE STRUCTURE: Old setup splits nonself/self; new setup single full_ctor
   - Old: BLAS-level parallelism (OpenBLAS multi-threaded within each phase)
   - New: Julia threading wrapper (explicit outer loop parallelism)
   - Cannot directly compare nonself+self vs full_ctor (different task decomposition)
