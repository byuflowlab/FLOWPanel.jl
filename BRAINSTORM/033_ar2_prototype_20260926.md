# 033 A-R2 — Prototype cooperative dagteam executor (2026-09-26)

**Verdict: prototype implemented, correctness fully validated (14/14 checks,
bitwise determinism, bitwise default identity), and in-situ overheads confirm
the A-R1 scale (h_2 ≈ 0.5 µs, h_4 ≈ 1.6–3 µs on median leaf classes inside
the live executor). Local j=4 screening shows NO solve-level gain
(w=2 0.98×, w=4 0.90× vs w=1) — as expected: at 4 threads the sweep is
WORK-bound (work/span 2.8), not span-bound, so shrinking 4 independent task
streams into 2 teams/1 team cannot pay. The prototype's target regime is the
span-bound high-j operating points; the decision-grade measurement is the HPC
1/8/16/32/64 ladder (A-R3), which this session does not submit.**

## What was implemented

Column-partitioned cooperative leaf products inside the `:dagteam` executor
(FastMultipole branch `flowpanel-20260817`, base `745af760`-dirty), behind a
runtime width toggle. All A-R1/A-T1 design rulings honored: column layout
only (row rejected by A-R1), persistent teams reused across the inner-sweep
block (no per-leaf task spawning), one publisher per team performs the
b−y−u update, cached LU `ldiv!`, and successor publication after all team
subtasks complete (lock/fence semantics untouched), and every spin wait calls
`GC.safepoint()` with a bounded (~10k-spin) yield escape (the A-R1 deadlock
lesson).

**Back-product cooperation (design fork, resolved lean and flagged):** teams
also cooperate on the backward products q_j = U_j x_j (column partition over
the source's n_j strength columns). Rationale: teammates are dedicated —
without this, at w=4 every back product would serialize onto the lone
publisher (a guaranteed local loss and a j64 work-imbalance risk). Same A-T1
column contract; the A-T2 model only split lower GEMVs, so this is a mild
extension of scope, trivially removable (two branch sites in the drain loop).

**Memory-ordering argument** (recorded in the code header): the publisher
pops under `plan.qlock`, whose acquire pairs with the lock release that
published every predecessor's strengths; the publisher's seq_cst job/seq
store then extends that happens-before edge to teammates' seq_cst seq load.
Teammate partial writes happen-before their `arrived` increment, which the
publisher's read pairs with before reducing. Reduction order is fixed
ascending member index ⇒ deterministic for fixed (w, partition).

**Split selection (A-T3 practical rule, as chosen):** every product with at
least 2 columns per member (`ncols ≥ 2w`) runs cooperatively — i.e.
essentially "all leaves with ptot > 0", per A-R1's finding that every real R4
shape down to p25 clears the split threshold (h_w ≈ 0.4–3 µs vs products
≥ 10 µs); the 2-per-member floor is only a degeneracy guard (no empty
blocks). Deliberately not restricted to hot leaves (A-T3 binding note). No
per-leaf measured-cost table in the prototype — with measured thresholds
~50× below median product cost, a static policy is within the rule's intent;
A-R3 can revisit if in-situ HPC h_w lands higher.

**Production default untouched:** `dagteam_coop=1` (FLOWPanel and
FastMultipole defaults) allocates no scratch, spawns no teammates, and takes
`coop === nothing` branches in the drain loop — the solo path is the
pre-change code (the only structural change is the pure extraction of
`dagteam_finish_lower!`). Bitwise identity verified below — note the
verification compares a `coop=1` build against the coop build at `teamw[]=1`,
both on this session's code; identity to the pre-change executor rests on the
diff being pure code motion (audit-verified), not on a cross-commit run.

## Local screening (R4, 58192 panels, j=4, paired same-process)

`timing_R4.csv` / `timing_summary_R4.csv` / `time_R4.log`. One solver
(`dagteam_coop=4`, champion R4 knobs, tolerance 3.43e-7), arms = `teamw[]`
∈ {1,2,4} toggled between cold (zero-initial-guess) solves, interleaved
w=1,2,4 per round, warmup solve per arm first, 5 rounds (021 ruling 5/7).
All 27-iteration solves; per-round deltas vs w=1 constant across rounds
(3.53e-7 / 4.15e-7 — deterministic); warmup arms independently certified
(w=1 1.09e-6 local anchor; w=2/4 0.98/0.92e-6, better than the anchor).

| arm | min (s) | median (s) | speedup vs w=1 (median) |
|---|---:|---:|---:|
| w=1 (production dagteam+backoff) | 6.115 | 6.226 | 1.000× |
| w=2 (2 teams of 2) | 6.273 | 6.375 | 0.977× |
| w=4 (1 team of 4) | 6.857 | 6.911 | 0.901× |

**Reading:** at j=4 the sweep is work-bound (gate-0 work/span = 2.8; W/4 ≫
L), so w=1's four independent leaf streams already saturate the machine;
teams reduce the number of independent streams to 2/1 and add coordination
— a structural, expected local loss, not evidence against the design. The
A-T2 model's prize (w=4 sweep ceiling 3.21×/2.53× at c=0/8 µs) exists only
where the critical path binds, i.e. j ≳ 16–64. **j-scaling is NOT measurable
on this 4-thread host; A-R3's paired j64 A/B on HPC is the decision gate.**

## Caveats (binding)

- **Local screening only.** j=4 on Ryan's laptop-class host; w=4 uses ALL
  local threads, so team-vs-breadth trade-offs at fixed budget are not
  observable here. The negative local speedup is regime-consistent, not
  dispositive either way. Decision-grade numbers require the HPC
  1/8/16/32/64 ladder with the paired uninstrumented protocol (A-R3 / A-G
  gate: team-of-4 must beat dagteam+backoff by >~15% at j64).
- Both checkouts dirty (banner: fp `c866f6f`-dirty, fm `745af760`-dirty);
  nothing here is campaign evidence. No commits made (per task boundary).
- h_w probe timings ran with the other team's publisher spin-waiting on the
  epoch (mirrors, imperfectly, real contention); run-to-run w=4 spread on
  median classes was ~2–10 µs across the two probe invocations.
- Certification gates were anchored to the w=1 arm where the champion
  tolerance is uncalibrated (R1 entirely; R4 marginally at this host —
  w=1 itself read 1.09e-6 vs the 1e-6 absolute target). All w>1 arms
  matched or beat their w=1 anchor.
- Back-product cooperation extends the A-T2-modeled scope (lower GEMVs
  only); if A-R3 wants the model-pure variant, it is a two-branch revert.
- **Determinism requires nw % w == 0** (clear-context review, 2026-09-26):
  leftover workers (nw mod w) drain the shared queue solo, so an eligible
  task computes as one GEMV or as a block-split reduction depending on which
  worker wins the pop — run-to-run bitwise reproducibility (A-T1 clause 2a)
  is then schedule-dependent. All validated/timed configs here (nw=4,
  w ∈ {1,2,4}) have zero leftovers; exact-arithmetic equivalence and
  certified accuracy hold regardless. A-I1 should enforce or re-disclose.
- The stats channel does not yet separate publisher wait time inside
  `busy_lower_ns` for cooperative leaves; per-class in-situ h_w on HPC
  should reuse the probe pattern in `fgs_coop_executor_ar2.jl` (MODE=time).
